The public demo uses the same creation interface as the main version, with simplified settings. Use your own API Key to try generation, editing, PPT renovation, and export.

## Configuration and Usage

The settings page and “Project Settings → Personal Settings” in the preview provide the same personal configuration. Both reuse the open-source forms, provider promotion popovers, and key setup guides. APIMart shows a price hint and Volcengine Agent Plan shows a direct-access hint. Hover or keyboard focus reveals the full benefits; selecting Volcengine also shows its brand introduction and setup steps. Both entry points share the saved configuration, and saving or resetting affects only the current visitor.

1. Open Settings and select Inferera, APIMart, or Volcengine Agent Plan.
2. Enter and save your API Key for that API provider. Keys are saved separately for each API provider, so switching configurations never sends one provider's Key to another.
3. Return to the home page to create a presentation. If a missing Key redirects you to Settings, your text input will be restored when you return.
4. When you first open each PPT's preview page, save the link shown in the dialog. You can also click “Share / Save Link” to copy it again later.

| API Provider | Text / Image Recognition Model | Image Generation Model |
| --- | --- | --- |
| Inferera | gemini-3-flash-preview | gemini-3-pro-image-preview |
| APIMart | gpt-5.6-sol / gpt-5.6-luna | gpt-image-2 |
| Volcengine Agent Plan | doubao-seed-2.1-turbo | doubao-seedream-5.0-lite |

Fixed API endpoints, model names, and model providers are hidden from personal settings and configured automatically for the selected provider. Expand Advanced Settings to adjust concurrency, description generation mode, and reasoning parameters. Reasoning budgets appear only when the corresponding reasoning switch is on; switching it off preserves the budget. The Volcengine option only supports **Keys dedicated to an Agent Plan subscription**; regular pay-as-you-go ModelArk Keys are not supported. Service tests use your saved personal configuration and make real calls to the provider's API. Tests for text, image recognition, image generation, MinerU, Baidu OCR, and Baidu image inpainting can run concurrently, each showing its own progress, result, and retry option, with a maximum wait of ten minutes. Save configuration changes before starting a new test; tests already running continue to use the configuration they started with.

Before starting generation or renovation from the home page, a lightweight call to your personal text model verifies the Key. If verification fails, you are directed to Settings with your text draft preserved, and no project is created.

For document parsing, OCR, or video voiceovers, enter the corresponding MinerU, Baidu OCR, or ElevenLabs credentials in your personal settings. The public version does not use fallback server credentials; without personal credentials, the corresponding service cannot complete its calls.

## Fields, History, and Sharing

- The extra description fields are fixed to “Images and Materials,” “Layout and Key Points,” and “Speaker Notes.” They cannot be added, removed, enabled, disabled, or reordered. Only the first two fields are passed to image generation.
- You can still edit each page's description body, the contents of these fields, and the generation requirements.
- The public version has no history list and does not support deleting projects. Direct requests to the history list API are also rejected.
- A shared link is the current PPT's preview URL and contains neither a visitor identifier nor an API Key. It opens the existing preview and editing pages, rather than creating a separate read-only copy.
- **Save this link if you want to return to the PPT. If you lose the link, you will no longer be able to access this PPT.**

The visitor identifier saved in your browser identifies your personal settings. If you clear browser data or switch browsers, you will need to enter your Keys again. Saving a PPT link and saving personal settings are separate actions. Resetting settings clears only the current visitor's configuration and API provider Keys; it does not affect other visitors.

## Self-Hosting the Public Version

Public mode is disabled by default in a standard deployment. The public version uses a separate configuration file:

```bash
docker compose -f docker-compose.demo.yml build
docker compose -f docker-compose.demo.yml up -d
```

Do not combine it with the standard `docker-compose.yml`. This configuration enables `PUBLIC_DEMO=true`, defaults to host ports 3000 for the frontend and 5000 for the backend, and uses separate container and network names. `FRONTEND_PORT` / `BACKEND_PORT` in `.env` can override the host ports. You still need to prepare `.env` and the uploaded files directory as in a standard deployment. Read the migration instructions below before upgrading an existing database.

## Viewing History as the Site Owner

Set `PUBLIC_DEMO_ADMIN_PASSWORD` to a long random password in the server's `.env`, restart the backend, then visit `/admin/history` and enter the password to view the paginated history list. With Docker Compose, run `docker compose -f docker-compose.demo.yml up -d --force-recreate backend` after changing `.env` to apply the configuration. Leaving the password empty disables this entry point.

The entry point does not appear in the public navigation. The regular `/history` page and public history API remain disabled. The page is read-only: clicking a project opens its existing preview in a new tab, with no rename or delete actions. The password is held only in the current page's memory and checked by the backend on every list request. After signing out or refreshing, you must enter it again. It is never written to browser storage or included in the URL. Use HTTPS for publicly accessible deployments.

## Migrating the Legacy Sponsor Demo

The `013` / `014` migrations in the legacy sponsor database have different meanings from the main version's migrations with the same names. Do not run the main version's `alembic upgrade head` directly. Use the migration tool to copy the data into a **new file that does not exist yet**:

```bash
uv run python scripts/migrate-public-demo.py \
  --source /backup/legacy-demo.db \
  --destination /staging/current-demo.db
```

The tool reads the source database without modifying it, creates the complete current schema in a new file, and preserves projects, pages, file paths, and tasks. It converts legacy browser tokens into hashed identifiers, assigns legacy personal Keys to the Inferera configuration, and records the actual database migration version. It refuses to overwrite an existing destination file, checks row counts and SQLite integrity, and outputs JSON results containing no credentials.

Rehearse with a copy before the production cutover. At the final cutover, pause writes to the old site, back up the database and uploads again, and migrate the final data. Place the destination file at `backend/instance/database.db` in the new version, retain the matching uploads, and start the new containers. Verify old PPT links, existing browsers' personal settings, and isolation for new visitors before restoring access. Retain the old container image, database, and uploads backup for rollback; do not give the new database to the old application. Rolling back to the old backup will not include data created after the cutover.

The database contains personal service credentials. Restrict its file permissions, and do not commit it to Git, include it in an image, or share it as a verification attachment.

## Verification

`frontend/e2e/public-demo.spec.ts` covers saving real settings, reloading, switching API providers, Key isolation, resetting, history blocking, sharing and copying, first-visit reminders, editing the description body and generation requirements, and handling public-mode loading failures.

`frontend/e2e/admin-history.spec.ts` covers real password validation, pagination, opening previews, signing out and refreshing, continued blocking of public APIs, and editing and selection behavior on the regular history page. When running the real tests, pass the `PUBLIC_DEMO_ADMIN_PASSWORD` from the verification backend's `.env` through an environment variable. This file disables screenshots, video, and network tracing to avoid recording the password.

`frontend/e2e/public-settings-behavior.spec.ts` additionally covers saving and reloading all editable settings, switching between providers' Key drafts, running all six tests concurrently, independent failures and retries, timeout recovery, and stopping polling after leaving Settings.

`scripts/verify-public-demo.py --partner apimart --flow` reads a Key from one line of standard input and performs real verification of text, image recognition, generation, and PPTX export. Add `--stream` to verify streaming outlines and descriptions; use `--image` to test the image service separately. For other API providers, use `--partner inferera` or `--partner volcengine` with the appropriate type of Key.

`--browser-tests` calls the real text and image recognition services concurrently in the browser, checks that an independent failure due to missing OCR credentials does not block the other tests, and verifies that other visitors cannot read the results. This mode disables screenshots, video, and network tracing, and clears test credentials when it finishes.

`--tools-project <测试项目ID>` requires a test project with generated images and reads a MinerU Token from the second line of standard input to verify PDF renovation and editable PPTX export. The script uses a temporary visitor and clears the saved test credentials when it finishes. Test projects are retained so you can inspect the results. Run it only in a verification environment; service calls consume provider usage.
