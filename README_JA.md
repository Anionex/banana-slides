## プロジェクトの背景
あなたもこのような苦境に陥ったことはありませんか？明日にプレゼンを控えているのに、PPTはまだ真っ白。頭の中には素晴らしいアイデアが溢れているのに、煩雑なレイアウトやデザイン作業に情熱を削がれてしまう……。

私（たち）は、プロフェッショナルかつデザイン性の高いプレゼン資料を素早く作成したいと切望しています。従来のAI PPT生成アプリは、「速さ」というニーズはおおむね満たしているものの、依然として以下のような課題を抱えています：

- 1️⃣ プリセットのテンプレートしか選べず、スタイルを柔軟に調整できない
- 2️⃣ 自由度が低く、複数回の修正が困難
- 3️⃣ 完成品の見た目が似通っており、同質化が激しい
- 4️⃣ 素材の質が低く、目的に対する的確さに欠ける
- 5️⃣ 画像とテキストのレイアウトがバラバラで、デザイン性に乏しい

これらの欠点により、従来のAI PPT生成ツールでは、PPT制作における「速さ」と「美しさ」という2つの大きなニーズを同時に満たすことが困難でした。自ら「Vibe PPT」と称していても、私の目にはまだ「Vibe」が足りないように映りました。

しかし、nano banana🍌モデルの登場ですべてが好転しました。🍌proを使ってPPTページを生成してみたところ、生成された結果は品質、美しさ、一貫性のどれをとっても非常に優れており、プロンプトで要求したすべての文字をほぼ正確にレンダリングし、参考画像のスタイルも忠実に再現していました。それならば、🍌proをベースに、ネイティブな"Vibe PPT"アプリを作ってみてはどうだろうか？と考えたのです。

## 🎯 機能紹介

<!-- i18n:creation -->
### 1. 柔軟で多様な制作パス
**アイデア**、**アウトライン**、**ページ説明**の3つの開始方法をサポートし、さまざまな制作習慣に対応します。
- **一言で生成**：テーマを入力すると、AIが構造化されたアウトラインとページごとの内容説明を自動生成します。
- **自然言語編集**：Vibe形式でアウトラインや説明を口頭で修正でき（例：「3ページ目をケーススタディに変更して」）、AIがリアルタイムで調整に応じます。
- **アウトライン/説明モード**：ワンクリックでの一括生成も、手動での詳細調整も可能です。

### 2. 強力な素材解析能力
- **マルチフォーマット対応**：PDF/Docx/MD/Txtなどのファイルをアップロードすると、バックグラウンドで内容を自動的に解析します。
- **インテリジェント抽出**：テキスト内のキーポイント、画像リンク、図表情報を自動的に識別し、生成のための豊富な素材を提供します。
- **画像の自動ライブラリ保存**：ドキュメントから解析された画像は、参照ファイルがプロジェクトに関連付けられた後、自動的にプロジェクト素材ライブラリに保存され、後で直接再利用できます。
- **スタイルリファレンス**：参考画像やテンプレートのアップロードに対応し、PPTスタイルをカスタマイズできます。

### Docker Compose を使用する🐳
docker compose を使用して、フロントエンドとバックエンドのサービスを素早く起動します。

<details>
  <summary>📒 Windows/Mac ユーザー向けの説明</summary>

**Windows または macOS** を使用している場合は、まず [**Docker Desktop をインストール**](https://docs.docker.com/desktop/setup/install/windows-install/) し、Docker が実行されていることを確認してください（Windows はシステムトレイアイコン、macOS はメニューバーアイコンで確認できます）。その後、ドキュメントと同じ手順に従ってください。

> **ヒント**: 問題が発生した場合、Windows ユーザーは Docker Desktop の設定で **WSL 2 バックエンド** を有効にしてください（推奨）。また、ポート **3011** と **5011** が使用されていないことを確認してください。

0. **コードリポジトリをクローンする**
```bash
git clone https://github.com/Anionex/banana-slides
cd banana-slides
```

1. **環境変数を設定する**

`.env` ファイルを作成します（`.env.example` を参照）：
```bash
cp .env.example .env
```

**（任意。起動後にユーザーインターフェースで設定することも可能です。[チュートリアルはこちらをクリック](https://ziy68cvfvu3.feishu.cn/wiki/GiNawdmpiinSRqkGspocqEWAnkh?from=from_copylink )）** `.env` ファイルを編集し、必要な環境変数を設定します：

<details>
<summary>クリックして詳細を展開</summary>
  
> **プロジェクト内の大規模言語モデル（LLM）インターフェースは AIHubMix プラットフォームの形式を標準としています。移行コストを抑えるため、[AIHubMix（ここをクリックして直接アクセス）](https://api.inferera.com/?aff=17EC) を使用して API キーを取得することをお勧めします。**<br>
> **ご注意：Google の nano banana pro モデルのインターフェース費用は高額になる可能性があるため、呼び出しコストにご注意ください。**
```env
# AI Provider格式配置 (gemini / openai / volcengine / vertex)
AI_PROVIDER_FORMAT=gemini

# Gemini 格式配置（当 AI_PROVIDER_FORMAT=gemini 时使用）
GOOGLE_API_KEY=your-api-key-here
GOOGLE_API_BASE=https://generativelanguage.googleapis.com
# 代理示例: https://api.inferera.com/gemini

# OpenAI 格式配置（当 AI_PROVIDER_FORMAT=openai 时使用）
OPENAI_API_KEY=your-api-key-here
OPENAI_API_BASE=https://api.openai.com/v1
# 代理示例: https://api.inferera.com/v1

# 商汤日日新 U1 图片模型（保留旧 Provider，图片走 OpenAI 兼容路径）
# 推荐：文本继续用 Gemini，只让图片走商汤
# IMAGE_MODEL_SOURCE=openai
# IMAGE_API_KEY=your-sensenova-api-key
# IMAGE_API_BASE=https://token.sensenova.cn/v1
# IMAGE_MODEL=sensenova-u1.5-lite

# 火山方舟 Agent Plans 配置（当 AI_PROVIDER_FORMAT=volcengine 时使用）
# 注意: Agent Plan 需使用专属 API Key 与模型名 (doubao-seed-2.1-turbo / doubao-seedream-5.0-lite)
VOLCENGINE_API_KEY=your-volcengine-api-key-here
VOLCENGINE_API_BASE=https://ark.cn-beijing.volces.com/api/plan/v3

# Vertex AI 配置（AI_PROVIDER_FORMAT=vertex）
# 需要 GCP 项目和服务账户密钥
# VERTEX_PROJECT_ID=your-gcp-project-id
# VERTEX_LOCATION=global
# GOOGLE_APPLICATION_CREDENTIALS=./gcp-service-account.json

# Lazyllm 格式配置（当 AI_PROVIDER_FORMAT=lazyllm 时使用）
# 选择文本生成和图片生成使用的厂商
TEXT_MODEL_SOURCE=deepseek        # 文本生成模型厂商
IMAGE_MODEL_SOURCE=doubao         # 图片编辑模型厂商
IMAGE_CAPTION_MODEL_SOURCE=qwen   # 图片描述模型厂商

# 各厂商 API Key（只需配置你要使用的厂商）
DOUBAO_API_KEY=your-doubao-api-key            # 火山引擎/豆包
DEEPSEEK_API_KEY=your-deepseek-api-key        # DeepSeek
QWEN_API_KEY=your-qwen-api-key                # 阿里云/通义千问
GLM_API_KEY=your-glm-api-key                  # 智谱 GLM
SILICONFLOW_API_KEY=your-siliconflow-api-key  # 硅基流动
SENSENOVA_API_KEY=your-sensenova-api-key      # 商汤日日新
# U1 生图请优先使用上面的 IMAGE_MODEL_SOURCE=openai 配置；此 Key 用于旧 LazyLLM 路径
MINIMAX_API_KEY=your-minimax-api-key          # MiniMax
KIMI_API_KEY=your-kimi-api-key                # 月之暗面 Kimi
PPIO_API_KEY=your-ppio-api-key                # PPIO 派欧云
AIPING_API_KEY=your-aiping-api-key            # AIPing 爱拼
...
```

> Banana Slides は、国内ベンダーが使用する LazyLLM オンラインプロバイダー SDK を明示的にパッケージ化しています：
> 豆包（Doubao）用には `volcengine-python-sdk[ark]`、通義千問（Qwen）/万相（Wanxiang）用には `dashscope`、GLM/智譜（Zhipu）用には `zhipuai` です。
> LazyLLM は `lazyllm install online-advanced` も公開していますが、PyPI の wheel ではそのグループが標準のインストール extra として公開されていない可能性があるため、Docker/ビルド済みイメージは代わりにこれらの明示的な依存関係に依存しています。
>
> デスクトップ（PyInstaller）ビルドは、すべての LazyLLM オンラインベンダーを明示的に登録します
> (qwen, doubao, deepseek, glm, kimi, minimax, sensenova, siliconflow, ppio,
> aiping, openai)。そのため、パッケージ化されたバックエンドが `Unsupported source: ...` にヒットすることはありません。
  
</details>


**新しい編集可能なエクスポート設定方法を使用して、より良い編集結果を得る**: [百度智能雲（Baidu AI Cloud）プラットフォーム](https://console.bce.baidu.com/iam/#/iam/apikey/list)（ここをクリックしてアクセス）で API KEY を取得し、.env ファイルの BAIDU_API_KEY フィールドに記入する必要があります（十分な無料枠があります）。詳細は https://github.com/Anionex/banana-slides/issues/121 の説明を参照してください。


<details>
  <summary>📒 Vertex AI 設定ガイド（GCP ユーザー向け）</summary>

Google Cloud Vertex AI を使用すると、GCP サービスアカウントを介して Gemini モデルを呼び出すことができます。新規ユーザーは無料クレジットを利用できます。設定手順：

1. [GCP Console](https://console.cloud.google.com/) に移動し、サービスアカウントを作成して JSON 形式のキーファイルをダウンロードします。
2. キーファイルをプロジェクトのルートディレクトリに `gcp-service-account.json` として保存します。
3. `.env` で以下を設定します：
   ```env
   AI_PROVIDER_FORMAT=vertex
   VERTEX_PROJECT_ID=your-gcp-project-id
   VERTEX_LOCATION=global
   ```
4. Docker を使用してデプロイする場合は、`docker-compose.yml` の関連するコメントアウトを解除し、キーファイルをコンテナ内にマウントして `GOOGLE_APPLICATION_CREDENTIALS` 環境変数を設定する必要があります。

> `gemini-3-*` シリーズのモデルには `VERTEX_LOCATION=global` が必要です。

</details>

2. **サービスを起動する**

**⚡ ビルド済みイメージを使用する（推奨）**

プロジェクトは Docker Hub でビルド済みのフロントエンドおよびバックエンドイメージを提供しています（メインブランチの最新バージョンと同期）。ローカルでのビルド手順をスキップして、迅速にデプロイできます：

```bash
# 使用预构建镜像启动（无需从头构建）
docker compose -f docker-compose.prod.yml up -d
```

イメージ名：
- `anoinex/banana-slides-frontend:latest`
- `anoinex/banana-slides-backend:latest`

起動後、アプリ内の **設定 → バージョン情報 → 更新を確認** から、現在のバージョンの SHA に基づいて利用可能な更新があるかどうかを判断できます。ソースコードから実行している場合も、現在の Git SHA を使用して判断されます。

**イメージをゼロからビルドする**

```bash
docker compose up -d
```


> [!TIP]
> ネットワークの問題が発生した場合は、`.env` ファイル内のミラーサイト設定のコメントアウトを解除してから、起動コマンドを再実行してください：
> ```env
> # 在 .env 文件中取消以下注释即可使用国内镜像源
> DOCKER_REGISTRY=docker.1ms.run/
> GHCR_REGISTRY=ghcr.nju.edu.cn/
> APT_MIRROR=mirrors.aliyun.com
> PYPI_INDEX_URL=https://mirrors.cloud.tencent.com/pypi/simple
> NPM_REGISTRY=https://registry.npmmirror.com/
> ```


3. **アプリケーションにアクセスする**

- フロントエンド：http://localhost:3011
- バックエンド API：http://localhost:5011

4. **ログを確認する**

```bash
# 查看后端日志（最后 200 行）
docker logs --tail 200 banana-slides-backend

# 实时查看后端日志（最后 100 行）
docker logs -f --tail 100 banana-slides-backend

# 查看前端日志（最后 100 行）
docker logs --tail 100 banana-slides-frontend
```

5. **サービスを停止する**

```bash
docker compose down
```

6. **プロジェクトを更新する**

**ビルド済みイメージを使用する場合（docker-compose.prod.yml）**

アプリ内の **設定 → バージョン情報 → 更新を確認** から、新しいバージョンがあるかどうかを先に確認することもできます。

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

**ローカルビルドを使用する場合（docker-compose.yml）**

注：コードを手動で修正した場合、この方法は適用されません。コードをプルした時のバージョンに戻す必要があります。

```bash
git pull 
docker compose down
docker compose build --no-cache
docker compose up -d
```

**注：サーバーデプロイの経験が全くない初心者向けに [初心者向けデプロイチュートリアル](https://github.com/ShellMonster/banana-slides/blob/docs-deploy-tutorial/docs/NEWBIE_DEPLOYMENT.md) を提供してくれた優秀な開発者の友人 [@ShellMonster](https://github.com/ShellMonster/) に感謝します。[こちらのリンク](https://github.com/ShellMonster/banana-slides/blob/docs-deploy-tutorial/docs/NEWBIE_DEPLOYMENT.md) から確認できます。**

<!-- i18n:source-deploy -->
### ソースからデプロイ

<!-- i18n:requirements -->
#### 環境要件
- Python 3.10 以降
- [uv](https://github.com/astral-sh/uv) - Python パッケージマネージャー
- Node.js 16+ および npm
- [FFmpeg](https://ffmpeg.org/) - 解説動画のエクスポートに必須。また、`libass` / `ass` 字幕フィルターのサポートが含まれている必要があります
- 有効な Google Gemini API キー
- （オプション）[LibreOffice](https://www.libreoffice.org/) - 「PPTリニューアル」機能で PPTX ファイルをアップロードする際に、PPTX を PDF に変換するために必要です。**あらかじめローカルで PPTX を PDF に変換してからアップロードすることを推奨します**。理由：サーバー側で LibreOffice を使用してレンダリングする場合、フォント（Microsoft YaHei、Calibri など）の欠如によりレイアウトが崩れたり、一部のエフェクトが完全に再現されなかったりする可能性があるためです。PDF ファイルをアップロードする場合は LibreOffice は不要です。Docker ユーザーがコンテナ内で PPTX アップロードのサポートを必要とする場合は、以下を実行してください：
  ```bash
  docker exec -it banana-slides-backend bash -c "apt-get update && apt-get install -y libreoffice-impress && rm -rf /var/lib/apt/lists/*"
  ```
  > 注意：この方法でインストールされた LibreOffice はコンテナの再構築後に失われるため、再インストールが必要です。

<!-- i18n:backend -->
#### バックエンドのインストール

0. **リポジトリをクローンする**
```bash
git clone https://github.com/Anionex/banana-slides
cd banana-slides
```

1. **uv をインストールする（未インストールの場合）**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

2. **依存関係のインストール**

プロジェクトのルートディレクトリで以下を実行します：
```bash
# macOS（Homebrew）
brew install ffmpeg-full
brew unlink ffmpeg 2>/dev/null || true
brew link --overwrite --force ffmpeg-full

# Ubuntu / Debian
sudo apt-get update
sudo apt-get install -y ffmpeg libass9

# 然后安装 Python 依赖
uv sync
```

これにより、`pyproject.toml` に基づいてすべての依存関係が自動的にインストールされます。

3. **環境変数の設定**

環境変数のテンプレートをコピーします：
```bash
cp .env.example .env
# 然后按照前述方法，打开编辑 `.env` 文件，配置你的 API 密钥
```

<!-- i18n:frontend -->
#### フロントエンドのインストール

1. **フロントエンドディレクトリに移動**
```bash
cd frontend
```

2. **依存関係のインストール**
```bash
npm install
```

3. **APIアドレスの設定**

フロントエンドは Vite proxy を介して `BACKEND_PORT` で指定されたバックエンドサービス（デフォルトは `http://localhost:5011`）に自動的に接続されます。変更が必要な場合は、プロジェクトのルートディレクトリにある `.env` で `BACKEND_PORT` を設定してください。

<!-- i18n:start-backend -->
#### バックエンドサービスの起動
> （オプション）ローカルに重要なデータがある場合、アップグレード前にデータベースをバックアップすることをお勧めします：  
> `cp backend/instance/database.db backend/instance/database.db.bak`
> 備考：デフォルト設定では、テンプレート、素材、完成品はすべて uploads/ フォルダ内に保存されます。

```bash
cd backend
uv run alembic upgrade head && uv run python app.py
```

バックエンドサービスは `http://localhost:5011` で起動します。

`http://localhost:5011/health` にアクセスして、サービスが正常に動作しているか確認してください。

<!-- i18n:start-frontend -->
#### フロントエンド開発サーバーの起動

```bash
cd frontend
npm run dev
```

フロントエンド開発サーバーは `http://localhost:3011` で起動します。

ブラウザを開いてアクセスすると、アプリケーションを使用できます。
